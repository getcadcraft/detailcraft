IFC 导出会将整个模型写成一个 IFC4 文件，可由 BIM 软件和 IFC 查看器打开。

## 导出

1. 在{{ui:输出}}组中选择{{ui:IFC}}。
2. 浏览器下载 `<name>.ifc`。状态栏会说明导出的内容，例如“已导出 IFC4：25 个零件、88 个紧固件、7 个基础、132 根钢筋。”

若模型中没有零件、基础或钢筋，状态栏显示“尚无可导出的内容。”

## 文件内容

| DetailCraft 中的内容 | IFC 文件中的内容 |
|---|---|
| 每个标高 | 一个建筑楼层（IfcBuildingStorey），隶属于同一项目、场地和建筑 |
| 轴网 | 一个 IfcGrid，包含其轴线及标签 |
| 柱、梁、支撑 | IfcColumn、IfcBeam、IfcMember（支撑），每个均为标准截面形状的拉伸体，并采用其实际尺寸 |
| 钢板、端板、底板 | IfcPlate |
| 孔和切角 | 从构件中切出的洞口（IfcOpeningElement） |
| 构件及其焊接钢板 | 带有部件编号标记的部件（IfcElementAssembly） |
| 螺栓和锚栓 | 带直径和长度的 IfcMechanicalFastener |
| 基础 | IfcFooting（独立基础），以混凝土强度等级文字作为其材料 |
| 每根钢筋 | IfcReinforcingBar，带钢筋编号、直径、面积和长度，沿其真实中心线扫掠，弯折处为真实圆弧 |

每个零件的标记即其构件编号。每个构件还带有一组名为“DetailCraft”的属性集，包含其编号、截面和重量。每个构件位于不高于其最低点的最高楼层中。材料按等级分组。

## 重新导出时保持稳定的 ID

每个构件的 IFC ID（GlobalId）由模型名称及该构件在模型中的 ID 计算得出。同一模型导出两次，ID 保持一致，因此用于比较版本的软件可以识别出变化的内容。

:::warning
更改模型名称会改变所有 ID。项目的各次发布之间请保持模型名称不变。
:::

## 检查文件

DetailCraft 的 IFC 文件会在其测试套件中由独立的 IFC 读取器回读验证。不同程序读取 IFC 的方式各不相同，因此在依赖该文件之前，请先用团队使用的软件打开它。CadCraft 的 BimCraft 应用也可以打开 IFC 文件。

## 导入

在{{ui:文件}}组中使用{{ui:导入IFC}}（或将 `.ifc` 文件拖放到视图上），即可根据 IFC2X3 或 IFC4 文件新建模型：

- **梁、柱、构件（支撑）和钢板**：其主体为 DetailCraft 所识别的单一拉伸截面，与截面库匹配，或保留为自定义截面；**轴网**和**标高**取自文件中的轴网和楼层。
- **孔：** 所有与构件某一面垂直的圆形洞口（对导入构件进行开洞的 IfcOpeningElement）：工字形或槽形截面的腹板或翼缘、钢管壁、钢板以及角钢的肢。穿过钢管两侧壁的孔只导入一次。
- **切角：** 从一端贯通工字形或槽形截面全宽的矩形开口，由顶部向下或由底部向上切割。
- **螺栓：** 每个 IfcMechanicalFastener 或 IfcFastener，包括其直径、长度、等级和类型（螺栓或锚栓），作为**散装螺栓**导入。散装螺栓会显示在视图、材料清单和 IFC 导出中，移动构件时保持原位。在未选中任何对象时，{{ui:特性}}面板会统计其数量，并提供{{ui:移除散装螺栓}}，供你改为添加连接时使用。

报告会按类别列出其余所有未导入的内容及原因：墙和楼板、基础和钢筋、长圆孔、圆钢管上的孔、连接（IFC 文件仅包含其钢板和螺栓，不包含生成这些连接的规则）。
